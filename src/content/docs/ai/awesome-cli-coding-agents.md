# Awesome CLI Coding Agents

**[bradagi/awesome-cli-coding-agents](https://github.com/bradagi/awesome-cli-coding-agents)**

## Overview

This is not a tool — it's a curated, actively maintained "awesome list" cataloging over 100 CLI coding agents (AI tools that read/edit repos and run commands directly in your terminal) plus the harnesses that orchestrate, sandbox, or extend them. It follows the standard [awesome.re](https://awesome.re) list conventions.

## What is it?

A single well-organized README split into two halves: **terminal-native coding agents** (open source, the "OpenClaw ecosystem" of forks/derivatives, and closed source) and **harnesses & orchestration** (session managers/parallel runners, orchestrators/autonomous loops, and agent infrastructure). Each entry is a one- or two-line summary with star count, license, and backing organization where relevant, sorted by GitHub stars within each section.

## Why use it?

The CLI coding agent space has exploded — dozens of Claude Code alternatives/rewrites, orchestrators that run several agents in parallel worktrees, and infrastructure projects around memory, sandboxing, and multi-channel access. This list is a fast way to survey that landscape, compare a new/unfamiliar tool against known ones, or find a specialized niche tool (e.g., a session manager, a scriptable headless daemon, a memory-first agent) without crawling GitHub search yourself.

## Installation

Not applicable — it's a reference document, not installable software. Browse it directly on GitHub or clone the repo to read the README offline.

## Basic Usage

Not applicable in the traditional sense. Use it as a reference:

1. Open the README on GitHub.
2. Jump to the relevant section (open-source agents, closed-source agents, session managers, orchestrators, agent infrastructure).
3. Compare entries by stars, license, and one-line description to shortlist candidates.
4. Follow the linked repo for full details/installation of whichever tool you pick.

## Key Features

- 100+ entries covering open-source agents, closed-source/proprietary agents, and the "OpenClaw ecosystem" of forks
- Separate section for harnesses/orchestrators that run multiple agents in parallel (session managers, autonomous loops, agent infrastructure)
- Stars, license, and backing-company tags on most entries for quick comparison
- Sorted by GitHub stars within each category for at-a-glance popularity signal
- Actively updated (list carries a "Last updated" date) and open to community PRs

## Top 5 Use Cases

- Quickly surveying the CLI coding agent landscape before picking one to adopt
- Finding a session-manager/orchestrator to run several agents (e.g., Claude Code + Codex + Gemini CLI) in parallel
- Discovering lesser-known but well-built niche agents (memory-first, sandboxed, ultra-lightweight, etc.)
- Benchmarking a new tool you're evaluating against the current field by stars/features
- Sourcing "competitors" sections when writing about or comparing coding-agent tooling (as used for this batch of pages)

## Competitors

As a curated list, its direct peers are other awesome-lists and landscape trackers rather than tools:

- **[awesome-ai-agents](https://github.com/e2b-dev/awesome-ai-agents)** style lists — broader AI agent lists not scoped to CLI/terminal tools
- Vendor/blog "state of AI coding agents" roundups — less structured, not community-maintained
- Terminal-Bench and similar benchmark leaderboards — rank agents by performance rather than cataloging the ecosystem

Notable tools referenced inside the list worth knowing for cross-comparison: **Claude Code**, **Aider**, **Cursor CLI**, **OpenCode**, **Codex CLI**, **Gemini CLI**, **Goose**, **Amp**, **Droid** (Factory), and orchestrators like **Claude Squad**, **Crystal**, and **claude-flow**.

## Pros

- Broad, well-organized coverage across open source, closed source, and orchestration tooling
- Fast comparison via stars/license/company tags without visiting each repo
- Community-driven via PRs, so it stays reasonably current
- Free and zero setup — just read the README

## Cons

- Purely descriptive — no benchmarking, testing, or quality vetting of listed tools
- Star counts and "last updated" dates can drift out of sync with fast-moving projects
- No license on the list repo itself, limiting reuse of the curated content
- Entries are one-liners; deeper due diligence still requires visiting each project
